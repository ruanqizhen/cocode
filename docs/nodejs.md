# Node.js 与 npm

> “九层之台，起于累土。” ——《老子》

在学习 Claude Code 之前，我们几乎都会遇到这样一条命令：

```bash
npm install -g @anthropic-ai/claude-code
```

对于长期使用 Python、Java 或 C++ 的开发者来说，这行命令多少有些陌生。

为什么不是 `pip install`？为什么不是下载安装包？为什么 Anthropic 会选择 Node.js 这一套原本属于 JavaScript 的生态，来分发这样一款重量级的 AI Agent？

想要回答这些问题，我们需要先认识两个名字：Node.js 与 npm。

它们并不是 Claude Code 的主角，却是整个 AI 工具链能够顺利运转的基础设施。理解它们，并不是为了成为前端开发者，而是为了理解现代 AI 编程工具为什么会采用今天这样的技术架构。


## Node.js

很多程序员第一次接触 JavaScript 时，都把它当作一种网页脚本语言。

这种印象其实并没有错。在很长一段时间里，JavaScript 几乎只能运行在浏览器中。它负责按钮点击、页面动画、表单验证，以及各种网页交互，却几乎无法接触操作系统本身。它不能读取本地文件，不能启动其他程序，也不能像 C++、Python 那样编写服务器程序。

直到 2009 年，一位名叫 Ryan Dahl 的工程师改变了这一切。

当时，Google Chrome 浏览器刚刚发布不久，其中内置了一款性能极高的 JavaScript 引擎——V8。Ryan Dahl 做了一件看似简单、却影响深远的事情：他把 V8 从浏览器中独立出来，又在外围封装了一层用于访问操作系统的底层接口，包括文件系统、网络通信、进程管理等能力。

最终诞生的，就是 Node.js。

从这一刻开始，JavaScript 不再只能生活在浏览器里，它第一次拥有了直接运行于操作系统之上的能力。

因此需要明确一点：Node.js 并不是一种新的编程语言，它只是 JavaScript 的运行时（Runtime）。

语言仍然是 JavaScript，只不过它终于走出了浏览器，拥有了真正接触操作系统的能力。



## 为什么 Node.js 如此受欢迎？

Node.js 的成功，并不仅仅因为它让 JavaScript 可以编写服务器程序，更重要的是，它天生就非常适合作为各种开发工具和自动化程序的运行平台。

### 高性能的 V8 引擎

首先，它直接使用 Chrome 浏览器中的 V8 引擎执行 JavaScript。V8 会将代码即时编译（JIT）为机器码，而不是传统意义上的逐行解释执行，因此拥有相当优秀的运行效率。对于命令行工具而言，这意味着更快的启动速度和更高的执行性能。

### I/O 密集型场景的完美适配

不过，真正让 Node.js 与众不同的，并不是速度，而是它处理输入输出任务的方式。

仔细观察一款像 Claude Code 这样的 AI Agent，你会发现，它真正花费时间的，并不是复杂计算，而是在不停地等待。

等待磁盘读取文件，等待 Git 返回结果，等待网络响应，等待测试程序运行结束……

如果采用传统的同步执行方式，每一次等待都会让整个程序停下来。而 Node.js 使用事件循环（Event Loop）和非阻塞 I/O 模型，在等待某一个任务完成的同时，可以继续处理其他工作，因此能够同时管理大量文件、网络连接以及子进程，而不会因为一次磁盘访问或网络延迟让整个程序陷入停顿。

### 优秀的跨平台能力

除此之外，Node.js 还有一个十分重要的优势——跨平台。

无论是 Windows、macOS 还是 Linux，同一套 JavaScript 代码几乎都可以直接运行。这意味着开发者无需针对不同操作系统分别维护多个版本，也让像 Claude Code 这样的工具能够覆盖几乎所有开发环境。

这些能力组合在一起，使 Node.js 很快超越了浏览器脚本的定位，成为今天最流行的命令行工具运行平台之一。



## Node.js 与 Claude Code

理解了 Node.js，再来看 Claude Code 为什么会选择它，就容易得多了。

很多人以为 Claude Code 是一个用 Go 或 Rust 编译出来的独立程序。事实上，它本质上是一个运行在 Node.js 上的大型应用。

当你在终端输入：

```bash
claude
```

真正启动的，其实是一个 Node.js 进程。

随后，这个进程开始扫描你的整个项目目录，分析源码结构，读取 Git 仓库状态，根据模型的要求执行测试、调用构建脚本，甚至修改磁盘上的文件。与此同时，它还需要一直保持与 Anthropic 服务器之间的长连接，持续接收模型返回的流式结果。

这些能力几乎全部建立在 Node.js 提供的底层接口之上。

例如，文件读写来自 fs 模块；启动 Git、Python、npm 等外部程序依赖 child_process；而网络通信则由 HTTP 相关模块负责。

可以说，Claude Code 的 AI 模型负责思考，而 Node.js 则负责把这些思考真正落实到你的电脑上。

Anthropic 之所以选择 Node.js，并不是因为 JavaScript 更先进，而是因为它已经拥有成熟稳定的文件系统接口、优秀的跨平台能力，以及极其庞大的开源生态。对于开发团队来说，他们完全可以站在整个 Node.js 社区的肩膀上，把更多精力投入到 AI Agent 本身，而不是重新实现一套底层工具链。



## npm：Node.js 世界的软件中心

如果说 Node.js 是运行程序的引擎，那么 npm（Node Package Manager）就是整个 Node.js 世界的软件中心。

它的角色，其实与你熟悉的 Python 的 pip、Rust 的 Cargo、Java 的 Maven 十分类似。

开发者完成一个工具之后，可以把它发布到 npm 的中央仓库。其他人只需要一条命令，就能够自动完成下载、安装、依赖解析以及版本管理，而不需要再手工复制文件或配置复杂的环境。

经过十几年的发展，npm 已经积累了数百万个开源软件包，成为全球最大的开源软件仓库之一。今天，大量命令行工具，包括 Claude Code，都通过这种方式向开发者发布。

于是，我们最开始看到的那条安装命令，也就不再神秘了。

```bash
npm install -g @anthropic-ai/claude-code
```

其中，npm 表示启动包管理器，install 表示安装指定的软件包，而 @anthropic-ai/claude-code 则是 Claude Code 在 npm 仓库中的唯一名称。

最值得注意的是中间的 -g 参数，它代表 Global（全局安装）。

默认情况下，npm 会把软件安装到当前项目目录，仅供当前项目使用；而全局安装则会把程序放入系统的全局目录，并自动加入环境变量。这样一来，无论你当前位于哪个文件夹，只需要输入一条 claude 命令，操作系统就能够立即找到并启动它。

也正因为如此，大多数命令行开发工具都会采用全局安装的方式。



## 安装 Node.js

要运行 Claude Code，首先需要在本地安装 Node.js。

如果你只是第一次接触这套生态，那么最简单的办法，就是直接前往 Node.js 官方网站下载安装程序。安装过程与普通软件没有区别，一路点击"下一步"即可。安装程序会自动完成 Node.js、npm 以及环境变量的配置，对于绝大多数用户来说，这已经足够了。

如果你经常需要维护多个项目，或者不同项目依赖不同版本的 Node.js，那么更推荐使用版本管理工具，例如 fnm（Fast Node Manager）。

版本管理器最大的好处，在于可以同时维护多个 Node.js 版本，并且能够在不同项目之间快速切换，而不需要反复安装和卸载。这也是许多专业开发者更倾向采用的方案。

无论采用哪一种方式，最终安装完成之后，都建议重新打开终端，并执行下面两条命令进行验证：

```bash
node -v
```

如果终端能够输出类似下面的版本号：

```text
v22.15.0
```

说明 Node.js 已经安装成功。

随后继续执行：

```bash
npm -v
```

如果输出版本号，例如：

```text
10.9.2
```

如果同样能够看到 npm 的版本号，那么说明整个运行环境已经准备就绪。

至此，你的电脑已经接入了全球最大的 JavaScript 开源生态，也拥有了运行 Claude Code 所需的全部基础设施。



## 需要学习 JavaScript 才能使用 Claude Code 吗？

不需要。

安装 Node.js，并不意味着你必须学习 JavaScript。对于绝大多数 Claude Code 用户而言，Node.js 更像是一种运行环境，就像安装 Python 后，并不意味着你要研究 Python 解释器的实现原理一样。

只要 Node.js 正常安装，Claude Code 就可以运行。至于 JavaScript 的语法、Node.js 的 API，以及 npm 生态，都可以在需要时再逐步了解，而不是学习 Claude Code 的前置条件。
如果你本身就是 JavaScript 或 TypeScript 开发者，那么 Node.js 会让你拥有更多扩展 Claude Code 的能力；但对于 Python、Go、Rust、Java、C++ 等其他语言的开发者来说，完全可以把它当作一项底层基础设施来使用。
