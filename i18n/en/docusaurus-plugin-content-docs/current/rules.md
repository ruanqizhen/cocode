# Project Constitution

> "Learn the rules like a pro, so you can break them like an artist." — Pablo Picasso

When pair programming with Large Language Models (LLMs), we must face a cold technical reality: LLMs are essentially completely stateless. The model will not remember your project, nor will it automatically understand your engineering conventions.

Therefore, the problem is never "Will the AI remember?", but rather, how do you reinject rules into the context of every conversation.



## CLAUDE.md and the Dual-Track Memory System

Working with AI coding tools, you might quickly run into an annoying problem: they have no long-term memory. Every time you start a new conversation, its understanding of your project resets to zero.

At the beginning of every new Session, it knows nothing about your codebase.

To solve this pain point, Claude Code provides two sets of mechanisms to retain information across sessions:

* One is the Active Convention (`CLAUDE.md`) that you write yourself.
* The other is the Auto Memory automatically generated by the system.

The difference in experience after setting up the memory system is very obvious:

Without configuring `CLAUDE.md`, if you ask it to add an API interface, it might casually use `axios`, but your project uniformly uses `fetch`, leading to repeated rework.
After setting it up, it will follow your tech stack, directory conventions, and naming styles right from the start.

The difference lies not in "whether a certain conversation is amazing," but in long-term collaboration—how much nonsense you speak less.



### 1. Comparison of the Dual-Track Memory System

* Active Convention (CLAUDE.md): Written by developers, it is the explicit rule system of the project.
* Auto Memory: Extracted automatically by Claude, it is the experience precipitated during the collaboration process.

| Dimension | CLAUDE.md | Auto Memory |
| ---- | ------------ | -------------- |
| Author | Developer | Claude Auto-generated |
| Content Nature | Explicit Rules and Constraints | Experience, Preferences, Historical Facts |
| Scope | Project / User Level | Local Repository Level |
| Content Type | Architecture Norms, Tech Stack, DoD | Commands, Bug Causes, Environment Habits |



## Multi-Level Scope of CLAUDE.md

`CLAUDE.md` is not located in just one place; it has a clear hierarchical structure and follows the rule of "the more specific, the higher the priority":

### 1. User Global Level

`~/.claude/CLAUDE.md` or `~/.config/claude/CLAUDE.md`

* Cross-project common preferences
* Example: Default English replies, prefer pnpm



### 2. Project Level (Core Layer)

`./CLAUDE.md` or `./.claude/CLAUDE.md`

* Team shared rules
* Tech stack, directory structure, development specifications



### 3. Subdirectory Level

`src/module/CLAUDE.md`

* Only takes effect when accessing this directory
* Used for local specification isolation



### 4. Local Sandbox Level

`CLAUDE.local.md`

* Not committed to Git
* Stores sensitive or personal configurations



### 5. Enterprise Managed Level

Enterprise-level unified strategy (Managed Policy)

* Forcibly takes effect
* Cannot be overridden



### Override Rules

The more specific the level, the higher the priority.
For example, when there is a conflict between the project level and the user level, the project level takes precedence.



## /init Automation and Collaborative Generation

You don't need to write `CLAUDE.md` from scratch by hand:

```bash
/init
```

It will scan the project structure, dependencies, and build methods, and generate an initial rules file.



### Advanced Usage

* Interactive initialization: Can dynamically confirm rules during initialization.
* Multi-tool integration: Automatically absorb `.cursorrules`, `AGENTS.md`.
* Secondary Prompt optimization:

```text
Based on the current CLAUDE.md, please:
1. Supplement implicit engineering conventions.
2. Extract error-prone points.
3. Supplement critical development red lines.
```



## Five Golden Principles of Writing

### Principle 1: Specific and Verifiable

❌ "Write good code"
✅ "Use 2 spaces for indentation + camelCase"



### Principle 2: Keep it Concise

`CLAUDE.md` will be loaded frequently; if it is too long, it will dilute the context.



### Principle 3: Clear Structure

Use headings, lists, and sections to enhance readability.



### Principle 4: Continuous Cleanup

Outdated rules are more dangerous than no rules.



### Principle 5: Front-Load Critical Rules

The most important rules must be placed at the top of the file.



### Hidden Tricks

HTML comments will not enter the model's context:

```html
<!-- Remarks for human maintenance only -->
```



## Progressive Disclosure and Splitting Strategy

When rules expand, they should be split rather than stacked.

### @import Inclusion

```md
@docs/git.md
```

Function: Splice content into context (does not save tokens)



### .claude/rules Path Rules

```yaml
paths:
  - "src/api/*.ts"
```

Function: Trigger loading rules based on files



### AGENTS.md Unified Entry Point

Can serve as a unified cross-tool specification:

```md
@AGENTS.md
```

## Auto Memory (Automatic Memory Mechanism)

Claude Code automatically records collaboration experience.

### Storage Structure

```text
~/.claude/projects/<project>/memory/
├── MEMORY.md
├── build-commands.md
└── debugging.md
```



### Characteristics

* Stored locally
* Not committed to Git
* Automatically extracts experience




## DoD and Circuit Breaker Mechanism (Critical Completion)

### DoD (Definition of Done)

```text
`pnpm run build && pnpm run test` must return 0
Otherwise delivery is forbidden
```



### Circuit Breaker Mechanism

3 consecutive failures:

* Stop modification
* Output reasons
* Propose hypotheses
* Request human intervention



## Git Hooks Security Layer

```bash
pnpm typecheck || exit 1
pnpm lint || exit 1
```

Used to block erroneous code from entering the trunk.



## Troubleshooting Guide

### 1. Is CLAUDE.md Loaded?

Use `/memory` to check.



### 2. Is There a Rule Conflict?

Subdirectory rules may override global rules.



### 3. /compact Risks

Compressing context may cause:

* Subdirectory `CLAUDE.md` to temporarily fail



## FAQ

### Q1: Does CLAUDE.md increase tokens?

Yes, it will be loaded in every session.



### Q2: Does it need to be committed to Git?

Project-level must be committed.



### Q3: Do rule modifications take effect immediately?

Takes effect after a new session or `/clear`.



### Q4: Can it completely rely on AI auto-generation?

Not recommended. Critical rules must be designed by humans.
