# AI 成本控制

> “一丝一毫，关乎节用。” ——《朱子家训》

当开发者或研发团队从“偶尔用网页版大模型”转向使用 Cursor、Claude Code 或自主代理（Agent）进行全天候开发时，通常会遭遇第一次“账单冲击”。

一个普通的编码 Agent 在一个复杂的重构会话中，可能会进行上百次 API 调用。由于上下文的复利效应（每次对话都需要把之前的历史记录和几万行代码重新打包发送一次），这一个会话就可能悄无声息地烧掉 7 到 30 美元。对于一个 20 人的团队，如果不加节制，每月的纯 API 账单轻松就能突破上万美元。

其实，AI 编程的账单 90% 都烧在了毫无意义的输入 Token（阅读上下文）上，而不是最终生成的那几行代码上。只要掌握正确的上下文管理与工程杠杆，你完全可以在不降低代码输出质量的前提下，将整体成本削减 70% 到 85%。

## 复利噩梦

大模型虽然聪明，但它的计算是要真金白银付费的。为了省钱，我们必须先弄清大模型厂商极其精明的计费公式：

$$\text{总费用} = (\text{输入 Token} \times \text{单价}) + (\text{输出 Token} \times \text{单价}) - (\text{缓存命中 Token} \times \text{缓存折扣})$$

- 输入 Token（最烧钱的黑洞）：你发送给 AI 的提问、历史对话记录，以及引用的代码文件。在开发中，它往往占据了总体消耗的 80% ~ 90%。
- 输出 Token：AI 回复的代码。计算生成的代价高昂，其单价通常是输入的 3~5 倍。
- 缓存命中 Token（你的利润池）：如果前后两次提问，发送的文件内容有极高的重合度，模型在服务器端会直接复用缓存（Prompt Caching）。缓存命中的 Token 价格通常直接打 1 折到 5 折。这是我们防守的核心阵地！

可怕的“上下文复利效应”：在自动化的 Agent 会话中，当对话进行到第 50 轮时，上下文可能已经膨胀到了惊人的 200K Tokens。这意味着，你此时哪怕只是对 AI 说一句“测试通过了，继续”，它都会把之前 50 轮的历史记录全部打包重发一遍。这种滚雪球式的隐性复利，是压垮账单的最大元凶。

## 模型路由分级

在团队开发中，最大的金钱浪费是“无脑开满配”——无论遇到什么琐碎任务，都直接抛给最贵、最聪明的顶级模型（如 Claude 3.7 Sonnet 或是 Gemini 2.0 Pro）。事实上，日常编码中 60% ~ 80% 的任务是常规的体力活：加注释、格式化 JSON、重命名变量、写测试样板。这些任务用便宜的小模型，和用昂贵的顶级模型，结果是一模一样的。

我们必须建立模型分级协作战术（Tiered LLM Strategy）：

| 任务层级 | 推荐模型与策略 | 预估输入单价 (每百万Token) |
| --- | --- | --- |
| 体力活（补全/注释） | 本地模型 (Qwen3-Coder 14B) 或 极速便宜模型 (Gemini 2.5 Flash / DeepSeek-V3) | $0 ~ $0.14 (成本近乎忽略不计) |
| 日常主力开发 | 性价比甜点 (GPT-4o-mini / Claude 3.5 Haiku) | $0.15 ~ $1.00 |
| 高难硬骨头攻坚 | 神级推理 (DeepSeek-R1) 或 代码霸主 (Claude 3.7 Sonnet) | $0.55 ~ $3.00 (按需拔剑) |

在多智能体架构中，让昂贵的顶级模型负责高屋建瓴地制定重构计划（Planner），然后把步骤拆解，交由便宜的模型去执行具体的文件修改（Executor）。

## 上下文主动剪枝

“上下文是钱，上下文是钱，上下文是钱！”最典型的破产行为：向 AI 提问时，把整个项目的源文件（甚至连带 `node_modules`）直接打包扔进去（俗称无脑 `@Codebase`）。一个 200K Token 的项目扔进去，问一次大概就要 0.5 到 2 美元。

- 战术 1：靶向投喂，拒绝全局检索。如果你明确知道问题在哪，让工具仅读取 Git Diff 以及涉及到的相关函数签名。精确地输入 `@src/api/user.js`，而不是让大模型全文扫盲。
- 战术 2：使用 Repo Map 替代全文。Aider 和 Cursor 都支持生成一棵 `repo_map`。它仅用几千个 Token 就能概括整个代码库的目录结构和核心类/函数签名。它比直接塞 20 个完整文件便宜 50 倍，且依然能让 AI 准确感知全局。
- 战术 3：配置铁血的排除名单。把自动生成的打包产物（`build/`、`dist/`）和大型 `*.log` 文件严格写入 `.gitignore` 或 IDE 的 Exclude 列表中。物理切断 AI 误读这些垃圾文件的可能。

## 极限榨干缓存与自动压缩

除了管住手少发文件，我们还需要在通信协议层面“榨干”大模型厂商的规则。

### 顺序即金钱（极致利用 Prompt Caching）
大模型的 API 缓存机制（KV 矩阵缓存）对内容顺序极度敏感，它从头开始匹配。最佳实践：必须把静态的、巨大的内容（如庞大的系统指令、项目 `CLAUDE.md` 规约、全库 API 工具定义）永远放在对话的最前面；把动态的内容（用户的最新提问、当前报错 Log）放在最后面。设计良好的 Agent，能保证静态部分高达 80% 的体积次次命中 1 折的缓存白菜价。

### 自动会话压缩与“逐字剔除”（Verbatim Deletion）
千万不要让 LLM 去做“总结历史对话（Summarization）”，那会导致遗漏重要的文件路径和原始报错代码，引发可怕的幻觉。现代极客工具（如 Claude Code 或 Morph Compact）会在上下文达到阈值时进行异步逐字压缩：它会直接过滤掉历史记录中那些“你说的对，对不起，我马上改”的调试废话、重复生成的样板代码，仅保留“核心架构决策”和“代码精髓”。这能在不掉智商的情况下，瞬间斩断复利噩梦。

## 工具链优化与批量处理

- 工具延迟加载（Defer Loading）与语义缓存：当你的全自主 Agent 挂载了 10 个以上的工具（MCP 服务器、查数据库等）时，单是给大模型解释这些工具的用法就要耗费几万 Token。不要一次性加载，让 AI 动态搜索工具（Tool Search）；对于重复的数据库或 API 查询，使用 Redis + 向量建立“语义缓存”，直接返回上一次结果。
- 终极羊毛：时间换金钱（Batch API）：如果你有大规模、非实时的任务负载（如夜间 CI/CD 自动化代码审查、大规模补充遗留代码库的文档注释、批量生成回归测试），绝对不要使用同步 API。改用 OpenAI 或 Anthropic 的 Batch API，只要你愿意等待系统在闲时处理（通常几十分钟内），所有输入和输出成本直接强制打 5 折。

## 极简工作流省钱“三板斧”

即便不懂底层 API，身为开发者，养成以下三个习惯也能极大截断亏损：

- 护栏前置：无测试，不开 AI：如果有写好的测试用例，AI 有了靶子通常一次就能写对。如果没有测试用例，AI 可能会像无头苍蝇一样瞎猜试错 4 次，你其实是在为 AI 的“试错成本”买单。
- 小步提交，拒绝宏大叙事：让 AI 改 50 行，验证，提交；再改下一个 50 行。不要试图让它一次性重构 2000 行。失败率极高不说，一旦跑飞，产生的几万个废弃 Token 费用就全部打了水漂。
- 关闭 IDE 的“常驻自动补全”：像 Cursor 的 Tab 补全看着爽，但背后其实是模型在疯狂请求。如果你不是全天高强度写码，它一天能悄悄烧掉 5-10 美元且全是噪音。把补全改为按键手动触发，或者用本地的 14B 开源模型（0 成本）接管。

## 算力预算表

通过以上五个杠杆的实施，我们来核算一个 10,000 行核心代码项目，在为期 2 周开发中的成本差异：

- ❌ 土豪裸奔流（全选顶级模型 + 无脑全局扫库 + 无缓存）：约 $150 ~ $220。
- ✅ 工程大师流（混合路由 + 靶向投喂 + 缓存保活）：约 $12 ~ $18。

如果彻底抛弃“无脑全局常驻顶级模型”的做法，一名正常强度的个人开发者或小团队成员，每月的合理算力预算应该如下：

- 本地小模型兜底：$0，覆盖 60% 的基础机械任务。
- 中等在线模型（按量调用）：$5 ~ $15，应对主力功能开发。
- 顶级模型（API 应急重构）：$5 ~ $10，只在啃硬骨头时拔剑。
- 合计：$10 ~ $25 / 月。

这基本相当于购买一个普通的定额订阅助手，但因为你掌握了精确的路由与缓存调度，同样的预算能让你爆发出高出几个维度的顶级战力。省钱绝不是为了抠门，而是通过系统的工程纪律与架构控制力，把硅谷巨头们的庞大算力，一丝不苟地压榨为你真正的生产力。
